# LLM 并发配置

`MAX_CONCURRENT_LLM_CALLS` 是每个 Python 进程的总容量。一个进程内的线程和异步事件循环共享许可；交互请求超限返回 HTTP 503。`MAX_BACKGROUND_CONCURRENT_LLM_CALLS` 是该进程内更窄的后台通道，后台请求等待许可，随后同时占用总容量。取消排队会归还许可，重复释放不增加容量。

| 部署方式 | 许可作用域 |
| --- | --- |
| 单进程服务 | 所有使用该门限的调用共享一个池 |
| 桌面 server + worker | 两个独立池；上限 1 仍允许前台、后台各 1 个请求 |
| 多个服务进程 / 多个副本 | 每个进程各有一个池 |

这些配置控制本地工作压力，不是供应商账号或整个部署的硬并发/费用限制。部署总并发取决于服务进程数、worker 数和各自通道的实际工作量；需要硬上限时，在所有调用共用的 API 网关或供应商端设置。进程退出自动销毁其本地许可池，不承担其他进程的许可回收。更改配置后重启相关进程，避免运行中切换许可池。
